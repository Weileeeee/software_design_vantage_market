Design Pattern 1 — Singleton

06 / 11
🎯 Intent

Ensure a class has only one instance and provide a global access point to it.

📁 File

src/Config/Database.php

✅ Why needed

Every Repository calls the DB. Without Singleton, each call would create a new PDO connection — wasting memory & causing errors.

// src/Config/Database.php
final class Database ← ① final prevents subclassing
{
  private static ?PDO $instance = null; ← ② holds single PDO

  private function __construct() {} ← ③ blocks new Database()
  private function __clone() {} ← ④ blocks clone
  public function __wakeup() { ← ⑤ blocks unserialize
    throw new \Exception("Cannot unserialize.");
  }

  public static function getInstance(): PDO
  {
    if (self::$instance === null) { ← ⑥ lazy init
      $config = require 'config/database.php';
      self::$instance = new PDO(...$config);
    }
    return self::$instance; ← ⑦ always same object
  }
}
Code Walkthrough
① final class
Prevents any subclass from being created, guarding the singleton contract.
② $instance
private static ?PDO — holds the one shared PDO object. Starts as null.
③ ④ ⑤ guards
Private constructor + clone + wakeup seal all three PHP backdoors for creating a second instance.
⑥ Lazy init
The PDO connection is only created on first call — not at app boot. Saves memory if the DB is never needed.
⑦ return
Every caller — UserRepository, CartRepository, OrderRepository, etc. — receives the same PDO object.

📞 How it's used: Every Repository starts with
$pdo = Database::getInstance();

Design Pattern 2 — Strategy

07 / 11
🎯 Intent

Define a family of algorithms, encapsulate each, and make them interchangeable — without changing the client code.

📁 Files

Strategy/PaymentStrategy.php
Services/CheckoutSession.php
Strategy/CreditCardPayment.php

✅ Benefit (OCP)

Add a new payment method (e.g. PayPal) by creating one new class — zero changes to CheckoutSession or any existing code.

① Interface (contract)
// PaymentStrategy.php
interface PaymentStrategy
{
  // All strategies MUST
  // implement these two:

  public function pay(
    float $amount
  ): bool;

  public function
    getMethodName()
  : string;
}
② Concrete Strategy
// CreditCardPayment.php
class CreditCardPayment
  implements PaymentStrategy
{
  public function __construct(
    private string $cardNumber
  ) {}

  public function pay(
    float $amount
  ): bool {
    // charge logic here
    return true;
  }

  public function
    getMethodName()
  : string {
    return 'Credit/Debit Card';
  }
}
③ Context — CheckoutSession
// CheckoutSession.php
class CheckoutSession {
  private ?PaymentStrategy
    $strategy = null;

  // inject at runtime ↓
  public function
    setPaymentStrategy(
      PaymentStrategy $s
  ): void {
    $this->strategy = $s;
  }

  public function
    executeCheckout()
  : bool {
    // delegates to strategy
    return $this->strategy
      ->pay($this->cartTotal);
  }
}
CreditCardPayment EWalletPayment FPXBankingPayment CashOnDeliveryPayment — all implement PaymentStrategy and are swapped in at runtime

Design Pattern 3 — Observer

08 / 11
🎯 Intent

When one object (Subject) changes state, all dependent objects (Observers) are notified automatically.

📁 Files

Observer/StockSubjectInterface.php
Observer/StockObserverInterface.php
Services/ProductStockSubject.php
Services/CartObserver.php

✅ Why it matters

When a product is bought out, all carts holding that item are cleaned automatically — no manual polling or UI refresh needed.

Subject — ProductStockSubject.php
final class ProductStockSubject
  implements StockSubjectInterface
{
  // ① register cart as observer
  public function attach(
    int $productId, int $cartId
  ): void {
    $this->observerRepo->register(
      $productId, $cartId
    );
  }

  // ② remove cart from observer list
  public function detach(
    int $productId, int $cartId
  ): void {
    $this->observerRepo->deregister(...);
  }

  // ③ fire notification to observer
  public function notify(
    int $productId, int $newStock
  ): void {
    $this->observer->update(
      $productId, $newStock
    );
  }

  // ④ convenience: decrement + notify
  public function decrementAndNotify(...)
  : int {
    $new = $productRepo->decrementStock(...);
    $this->notify($productId, $new);
    return $new;
  }
}
Observer — CartObserver.php
final class CartObserver
  implements StockObserverInterface
{
  public function update(
    int $productId,
    int $newStock
  ): void {
    if ($newStock > 0) return; ← still in stock

    // stock = 0 → remove from ALL carts
    $cartIds = $this->observerRepo
      ->findCartsByProduct($productId);

    foreach ($cartIds as $cartId) {
      $this->cartRepo->removeItem(...);
    }
    $this->observerRepo->deregisterAll(...);
  }
}
⏱️ SEQUENCE
1. User adds item to cart → attach(productId, cartId)
↓
2. Stock_Observers row inserted in DB
↓
3. Checkout → decrementAndNotify() → stock = 0
↓
4. CartObserver::update() → removes item from all watching carts
